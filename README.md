# 矩形纸张裁切排样（小型印刷作坊）

输入母纸尺寸、刀缝、张数上限与各类成品需求，自动给出**贯通式（每刀贯穿当前余料）**
裁切方案：逐张排样图、按执行顺序排列的裁切步骤、实际成品数，并可导出裁切单。

- 后端：Python 标准库（`http.server` + `sqlite3`），**零第三方依赖**
- 前端：浏览器界面（服务端渲染 + SVG 排样图）
- 存储：SQLite（首次启动自动建表，无需手动初始化）

## 快速开始（Docker Compose 一键启动）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8000**

> 数据保存在名为 `papercut-data` 的卷中（容器内 `/app/data/app.db`），
> 删除容器不丢数据。停止：`docker compose down`。

也可以只用 Dockerfile：

```bash
docker build -t paper-cutter .
docker run -p 8000:8000 -v papercut-data:/app/data paper-cutter
```

## 本地运行（不用 Docker）

需要 Python ≥ 3.10，无需安装任何依赖：

```bash
python3 app.py
# 访问 http://localhost:8000
```

## 配置（环境变量）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8000` | HTTP 监听端口（容器内） |
| `DATA_DIR` | `./data`（容器内 `/app/data`） | SQLite 数据目录 |
| `DB_PATH` | `$DATA_DIR/app.db` | SQLite 数据库文件路径 |
| `SOLVER_TIME_LIMIT` | `30` | 单次求解的时间预算（秒），与“搜索状态数上限”共同约束搜索 |

Compose 中修改宿主机端口映射：把 `docker-compose.yml` 的 `"8000:8000"` 改为如 `"8080:8000"`。

## 使用说明

1. **新建任务**：填写母纸长宽、刀缝宽度、张数上限、搜索状态数上限，以及每种成品的
   长宽、份数、能否旋转，提交后自动求解。
2. **查看结果**：任务页展示逐张排样图（彩色=成品，浅灰虚线=余料，深灰=刀缝）、
   每张纸按执行顺序排列的裁切步骤、成品需求与实际产出对照。
3. **导出裁切单**：点击“导出裁切单”得到可打印页面（可直接打印或另存为 PDF），
   裁切单上标明**输入版本号**。
4. **修改输入**：任务页“修改输入”提交后生成新的输入版本（v2、v3…），
   **旧版本上的方案立即全部失效**；失效方案的裁切单导出会被拒绝（HTTP 409）。
   只改任务名称不产生新版本，方案保持有效。

### 输入规则（非法输入一律拒绝，不会写入数据库）

- 母纸长宽、成品长宽：正整数（mm）
- 刀缝宽度：非负整数（mm）
- 成品份数、张数上限、搜索状态数上限：正整数
- 至少一种成品；成品总份数 ≤ 1000，种类 ≤ 50

### 三种求解状态

| 状态 | 含义 |
|---|---|
| 已找到可行方案 | 输出逐张排样图、裁切步骤与实际成品数（满足全部份数，不保证最优） |
| 搜索已穷尽：无解 | 搜索空间已全部探索完，约束下不存在可行方案（可放宽张数上限等再试） |
| 搜索预算耗尽 | 达到状态数/时间预算被迫中止，**不能确定是否有解**；提高“搜索状态数上限”后重试 |

### 裁切规则保证

- 每一刀都贯通当前矩形余料（guillotine cut），步骤按可执行顺序输出；
- 每刀扣除刀缝宽度；成品互不重叠、不越界；
- 不可旋转的成品只按原始方向放置，可旋转的成品可旋转 90°；
- 使用的母纸张数不超过张数上限；实际成品数满足全部份数。

## 运行测试

```bash
python3 -m unittest discover -s tests -v
```

包含求解器正确性测试（含独立的裁切步骤模拟校验：每刀贯穿当前余料、刀缝扣除、
成品与废料恰好铺满母纸）与 Web 层测试（非法输入不保存、版本失效、导出拒绝、
预算耗尽重试等）。

## 项目结构

```
app.py          HTTP 服务与路由（标准库 http.server）
solver.py       贯通式排样求解器（DFS + 记忆化 + 状态预算）
validation.py   输入校验（非法输入绝不落库）
db.py           SQLite 存储（任务 / 输入版本 / 成品 / 方案）
views.py        服务端 HTML 渲染
svgrender.py    逐张排样 SVG 生成
static/style.css
tests/          求解器与 Web 层测试
Dockerfile / docker-compose.yml
```

## 求解算法简介

按“先大后小”的顺序逐件放置成品：每件可放入任意已开启母纸的任意空闲矩形
（置于左下角），或开启一张新母纸；放置后按两种贯通切法（先竖后横 / 先横后竖）
把余料一分为二并在切口扣除刀缝。深度优先搜索 + 失败状态记忆化 + 对称去重，
找到第一个可行方案即返回；探索状态数超过预算（或超时）即报告“预算耗尽”，
只有整个搜索空间穷尽才报告“无解”。
